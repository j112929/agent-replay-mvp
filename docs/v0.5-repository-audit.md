## Missing or incomplete

Versioned supervised transition export from legacy Refund capture, aligned history,
grouped dataset manifests/JSONL, independent prediction metrics/error artifacts,
shadow mode, bounded mismatch correction, CPU supervised next-observation training,
world-model registry/shadow promotion, local open-weight optional backend, public
safe evaluation artifact view and ablation experiment CLI. Existing LLM predictor
is schema validated but provider quality is mock-only tested; no GPU claim.

## Integration decisions

Keep `planning.WorldModel.predict(context, action, config)` and add an adapter for
`predict_next`/bounded batches rather than breaking existing providers. Reuse
`planning.dataset` transition records and extend optional provenance/history fields;
world_model/dataset.py produces a versioned training artifact, not a second trace
store. Legacy Refund extraction requires explicit trusted adapter opt-in and uses
actual captured input/output; no inferred real observations from hypotheses.

The first deterministic Refund predictor is a correctness oracle using public
state and documented synthetic rules. Real environment execution is independent,
uses existing synthetic lookup/refund doubles, and enforces business limits before
refund execution. Optional stale/missing context creates recoverable observation
errors; no retry may repeat an irreversible operation. Shadow executes only the
independently authorized baseline action, even if a different candidate ranks first.

Training initially includes a CPU categorical supervised predictor with measured
training loss and held-out exact prediction evaluation. Local Hugging Face/PEFT
SFT and inference are optional, no model downloads or remote code by default.
Reuse checkpoint hashing; no online weight updates or RL scheduler changes.
Promotion requires held-out quality/safety/cost evidence and independent shadow
execution evidence. Missing evidence blocks active promotion; no automatic deployment.

## Dependency and file-level sequence

1. Extend planning interfaces; world_model/{dataset,evaluation,refund}.py and CPU
   tests using existing Refund doubles: predict next observation from real traces.
2. Extend PlanningConfig/PlanningAgent with shadow and correction configuration;
   retain legacy active defaults when enabled, add v0.5 explicit preset/config adapter.
3. world_model/{training,registry,local}.py: CPU supervised model, optional local
   HF/LoRA, checkpoint validation, offline evaluation and shadow promotion checks.
4. planning experiment/CLI aliases, Refund paired ablations and existing reports;
   static imported evaluation view, CI, version 0.5.0, release notes and package sync.

No SQL migration or trajectory v2 version bump. New records use associated optional
metadata. Existing 0.4 configuration remains valid; stricter action authorization
never falls back to host execution. Rollback uses disabled planning and previous
package; retain immutable artifacts for audit. Optional dependencies must not be
imported by base SDK/CLI. Test CPU, mocked provider, optional HF/GPU and distributed
paths separately; unexecuted hardware validations stay pending.
