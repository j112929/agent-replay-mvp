# v0.5: Predict → Plan → Execute → Observe → Compare → Correct → Learn

This optional subsystem extends the existing Agent Benchmark, Replay & Regression
control plane. [Actual repository audit](v0.5-repository-audit.md). Existing capture,
trajectory v2, replay, local benchmark, rollout/Ray/DDP/GRPO and SaaS interfaces remain.
No SQL migration, production execution capability or hosting change is introduced.

## Reproducible CPU experiment

```sh
python -m pip install -e '.[dev]'
agent-replay planning benchmark --output .replay/v05 --tasks 20
python scripts/check_world_model_demo.py .replay/v05
```

Use a fresh directory. The command executes matched synthetic Refund tasks in
baseline, shadow, active, active+self-correction, H=1/3/5, no-risk and no-uncertainty
modes. Baseline and the extra safe-policy rule controller are no-world-model ablations. Compare the safe-policy controller to isolate action-rule changes from the world-model contribution. It writes existing run/results,
trajectory v2, JSON/HTML/JUnit reports and paired comparison artifacts. The example
quality gate measures whether added cost/tool calls violate a 25% increase budget.
A completed experiment returning exit 0 is not a PASS release decision; inspect
`quality-gate.json` or invoke the existing `benchmark gate --policy` command.

World models never receive the executor. Refund execution reuses the implementations
of existing `demo.lookup/refund` synthetic doubles once per action, inside the
existing Capture boundary. There are no live financial operations. The independent
execution policy forbids refunds above approval/request limits, unknown actions,
stale execution versions and repeated irreversible operations. Candidates include
lookup, approval, alternate refund amounts, request-information, stop and escalation.
An oracle predictor has the documented public business rules; it does not know
private first-call context-drift fixtures. This permits actual prediction errors
and measurable correction, not an assigned planner success result.

Shadow predicts/ranks but executes only the independently validated baseline
choice. Active selects the best-ranked first action, then replans from the real
state (MPC). Bounded self-correction is separate: actual observation errors stop
when correction is disabled; when enabled, mismatch may trigger up to `max_replans`
additional correction decisions, within the existing real-action/task budgets.
Policy violations always stop by default, even when correctly predicted. Action
idempotency/resource identity is owned by the execution adapter, never the model.
Online replanning does **not** update model parameters.

## Configuration and SDK

`PlanningConfig` keeps its earlier defaults and positional field order. The new
`world_model.config.configuration` adapter provides the v0.5 preset: disabled,
shadow, K=3, H=1, N=2, ≤12 predictions, ≤5,000 ms; preset reward/risk/uncertainty/cost weights are 1/1/0.5/0.1. Existing enabled legacy configs
remain active. All modes are opt-in; `mode=disabled` delegates directly to baseline.

```sh
agent-replay planning run --config examples/benchmarks/predictive-deploy/v05-refund.json \
  --tasks 20 --output .replay/refund-active
agent-replay planning compare .replay/v05/baseline .replay/v05/correcting
agent-replay planning replay .replay/v05/active/planning/sessions/SESSION_ID.json \
  --output .replay/rescored.json
```

The replay command only recomputes stored hypothetical scores under optional
`--config` weights. It never executes a model, agent or tool, and does not overwrite
the original. Use existing recorded playback for real execution inspection.

The compatible world model protocol remains `predict(AgentContext, CandidateAction,
PredictionConfig) -> PredictionDistribution`. `WorldModelAdapter` adds
`predict_next(history, action, task)` and a bounded sequential `predict_batch`.
`SampledCandidateGenerator` accepts a trusted async policy sampler (including an
LLM provider) and reuses candidate schema checks/deduplication. It receives copied context and charges generation costs for all samples, including deduplicated samples. Trusted samplers must bound their own provider request sizes and report generation cost; hosted simulation does not accept such callbacks. `RetryingWorldModel`
permits ≤2 model-response retries within one deadline, reserves their token budget
and marks usage/cost unknown when failed response billing cannot be determined.
No predicted action executes through these adapters.

Scores retain separate reward, risk, uncertainty, execution-cost and final-score
fields, sample-score variance and raw outcome entropy plus configuration provenance. Reward/risk/uncertainty use the controlled
0–1 domain; cost is USD with an explicit unit-sensitive coefficient. `value_weight`
and risk/uncertainty/cost weights are configurable; these scales/weights are not
learned calibration. The deterministic oracle has zero uncertainty, so an uncertainty
ablation need not change behavior. No MCTS or beam-search claim is made.

## Authorized transition dataset

```sh
agent-replay world-model dataset build .replay/v05/correcting/trajectories \
  --authorize-training --output .replay/refund-data
agent-replay world-model train .replay/refund-data --output .replay/models/cpu
agent-replay world-model evaluate .replay/refund-data \
  --checkpoint .replay/models/cpu.reference.json --checkpoint-root .replay/models \
  --output .replay/cpu-evaluation.json
```

`world_model.dataset` extends the existing real-transition extractor, not trajectory
storage. JSONL rows include actual action/observation alignment, history, reward,
terminal status, environment/tool-schema versions and trace/step provenance.
Strict credential/PII sanitization and optional repeatable `--sensitive-field` rules run before extraction; redacted examples are excluded. Explicit operator authorization and an authorized source marker/adapter are required;
an imported marker alone is not consent. Synthetic/simulated/replay records,
redacted data, unsafe outcomes and denied operations are not training transitions.
An explicit `--adapter legacy-refund` converts old captured Refund doubles without
inventing state deltas; the predictive Refund oracle intentionally refuses this
legacy environment version rather than claiming it can predict missing state.

Dataset manifests hash each private JSONL split and the versioned source examples.
Exact examples deduplicate, rows order deterministically, and splits keep scenario/
family groups and trajectory provenance together. Hash-verified train/validation/test
loaders reject corruption. A supplied scenario grouping must correctly represent
related families; semantic near-duplicate detection is not automatic. JSONL is
implemented; Parquet is deferred to avoid a mandatory Arrow dependency.

Independent evaluation writes `world-evaluation.v1` with linked prediction/trace/
step/model/environment IDs, field differences, exact/schema/terminal accuracy,
transition consistency, error categories, per-field MAE/RMSE, latency, tokens/cost
and failure rate. HF evaluation accepts an explicit `--cost-per-million` estimate; otherwise cost remains unknown and cannot pass a required cost gate. Binary NLL/Brier/ECE/reliability use explicit success events and
observed terminal labels only. One-class ROC/PR AUC remains null. Missing model
usage/cost stays unknown, including failed predictions; text similarity is never a
success label. Numeric errors from different units are never averaged together.

## Optional local SFT / LoRA

```sh
pip install -e '.[world-model]'
# Prepare an operator-owned local HF checkpoint under an explicit checkpoint root.
# Seal it with existing: agent-replay rollout seal-checkpoint /abs/root/base
agent-replay world-model train .replay/refund-data --backend hf-sft \
  --config local-sft.json --output /abs/root/world-sft
agent-replay world-model evaluate .replay/refund-data --backend hf \
  --checkpoint /abs/root/world-sft.reference.json --checkpoint-root /abs/root \
  --output .replay/hf-evaluation.json
```

Config keys: `base_checkpoint` (existing sealed reference), absolute
`checkpoint_root`, `device` (`cpu` or explicit `cuda`), `epochs` (1–10),
`learning_rate` (>0, ≤0.1), `max_steps` (1–1000), `max_sequence_length` (64–4096),
`lora` (boolean), explicit model-specific `target_modules`, and integer `seed`.
Model size/architecture is not hardcoded. LoRA uses rank 8/alpha 16 as an initial
engineering baseline. Local-only loading, safetensors, no trusted remote Python,
masked prompt labels, gradient clipping, validation loss and sealed epoch checkpoints
are implemented. Oversized sequences reject instead of truncating target labels.
Optimizer-state resume is not implemented; restart from a model checkpoint is a new
training run. Existing distributed RL optimizer recovery is unchanged and is not
misrepresented as SFT optimizer resume.

`tests/world_model_hf_smoke.py` constructs a tiny GPT2/tokenizer locally, performs
real CPU LoRA updates, checks nonzero learned adapter weights, evaluates validation
loss, verifies immutable checkpoints, reloads the local predictor and exercises its
structured-output boundary. This is **not** evidence of useful generated forecasts.
No external checkpoint, paid inference or GPU is needed for the smoke. Large models,
Qwen-specific target modules, CUDA, NCCL and vLLM world-model inference remain pending.
An existing OpenAI-compatible vLLM endpoint can be explicitly configured through the
provider registry; no dedicated new GPU serving infrastructure is introduced.

Local HF callbacks are trusted SDK-only inference, with bounded generation length
and best-effort generation max-time; blocking tensor operations cannot be preempted
by asyncio cancellation. Run them under the existing benchmark hard deadline or an
operator-isolated worker. They are not exposed by hosted mock-only simulation.

## Registry, shadow promotion and rollback

`world-model promote` accepts checkpoint/root, candidate and `--baseline-evaluation`,
real `--shadow-run`, explicit `--policy`, and a local `--registry`. Required policy:

```json
{"min_exact_match":0.95,"max_prediction_failure_rate":0.01,
 "max_latency_ms":1000,"max_cost_per_prediction":0.01,
 "min_heldout_groups":20,"min_shadow_tasks":20,
 "max_exact_match_drop":0,"max_brier_increase":0.02}
```

These are example thresholds, not universally validated production settings. The
gate rejects training/evaluation overlap, mismatched versions/datasets, insufficient
coverage, missing/poor calibration or cost evidence, prediction regressions and
absent/failed/unsafe real shadow execution. Registry records reuse existing immutable
content-addressed objects and checkpoint manifests. Active eligibility changes only
an offline local reference; it never deploys or changes a running policy. `registry.rollback`
can restore a previously approved object. No automatic promotion or online fine-tuning.

The default categorical learner deliberately refuses unseen feature support. A
selected-action-only dataset may lack alternate candidate transitions; shadow
planning can therefore fail even when offline next-observation accuracy looks good.
This blocks promotion and is a meaningful gap, not a reason to fabricate fixtures.
The positive promotion test separately collects sufficient independent clean data
and runs real shadow execution before permitting an offline reference.

## Product views and publication

Open `/world-model.html` from the existing workspace's Predictive Planning link.
Planning Explorer and Prediction Inspector import v2 trajectories locally and reuse
the existing candidate/prediction/actual/correction component. World Model Evaluation
shows accuracy/calibration/errors; Planning Benchmark shows paired success/cost/
latency/tool calls and ablations. Browser imports never upload data or execute Python.

`world_model.publish.public_report` exports an allowlist of aggregate metrics and
model provenance, excluding raw trajectories, tool fixtures, histories, source IDs,
training data and model checkpoint paths. The checked-in public artifact contains
synthetic evidence only. Do not copy private experiment directories into `dist/`.

## Verification and operational limits

New unit tests cover the oracle, legacy conversion, consent, grouped datasets,
independent evaluation, shadow parity, bounded correction, cost accounting, real
CPU fit/checkpoint integrity, retries and held-out/shadow promotion/rollback.
Existing Refund fail→pass→fail, benchmark, replay, security, SaaS and rollout tests
remain required. GitHub Actions separates base CPU evidence from optional-library
CPU LoRA; GPU validation is explicitly pending. No new scheduler, database, training
cluster, host execution fallback or public secrets are introduced.

Primary API references used for the optional backend: [Transformers local loading](https://huggingface.co/docs/transformers/main/models)
and [PEFT LoRA configuration/save/load](https://huggingface.co/docs/peft/main/package_reference/lora).
