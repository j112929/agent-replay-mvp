# Probabilistic decision intelligence — v0.6

This optional CPU research extension preserves the benchmark/evaluation/replay/
regression product. It does not implement a second agent runtime, production
world model, paid provider experiment or autonomous model update.

## Reproduce the experiments

```bash
pip install -e '.[dev]'
agent-replay probabilistic run --experiment calibration \
  --config examples/probabilistic/calibration.json --output .replay/research/calibration
agent-replay probabilistic run --experiment risk_planning \
  --config examples/probabilistic/risk_planning.json --output .replay/research/risk
agent-replay probabilistic run --experiment horizon_reliability \
  --config examples/probabilistic/horizon.json --output .replay/research/horizon
agent-replay probabilistic publish \
  .replay/research/calibration/experiment.json \
  .replay/research/risk/experiment.json \
  .replay/research/horizon/experiment.json --output .replay/research/public-summary.json
```

Use a new output directory each time; existing evidence is never overwritten by
`run`. `python -m agent_replay.probabilistic.experiments.runner` accepts the same
run flags. JSON configuration avoids a required YAML dependency. Start with
`examples/probabilistic/smoke.json` for a fast, deliberately inconclusive CI demo.
Larger configs run actual repeated synthetic trials, not preselected outcomes.

Open each experiment's `index.html`; existing benchmark HTML/JSON/JUnit and v2
trajectories live under each run. Import `public-summary.json` into the existing
`world-model.html` workspace to use Calibration Lab, Risk Planning Lab and Horizon
Reliability Lab. It is a local aggregate artifact reader; it cannot execute Python.
Public export accepts only completed explicitly synthetic experiments and numeric
allowlists. Private observations, task/group IDs, training groups, fixture payloads,
credentials and storage paths are not published.

## What actually runs

The bundled in-memory workflow has route choices with different returns and rare
severe losses. A separate environment PRNG verifies actual transitions. A separate
world-model implementation predicts probabilities, with an explicit version that
underestimates rare failures and an environment shift stratum. No HTTP, shell,
payment, cloud or database execution capability exists in this adapter.

For horizon trials, health can degrade stochastically; repair consumes time/cost
without advancing the goal. Open-loop actions are cached. Periodic, error-triggered
and uncertainty-triggered replanning receive newly observed state via the existing
PlanningAgent. Its execution authorization, state version checks, real step Capture
and irreversible-operation protection still apply. Model predictions receive copies,
never an executor. Mandatory safety checks also apply to cached actions.

The research sampler shares the existing WorldModel protocol, CandidateAction,
AgentContext and pure distribution draw. It supports K<=8, M<=32, H<=32 in associated
files; interactive PlanningConfig limits remain unchanged. The existing planner
session contains compact root predictions, decision scores and links to complete
simulated futures. Hypothetical steps never become real trajectory tool events.

## Probability semantics and leakage controls

SuccessForecast distinguishes task success, action outcome and model-confidence
scopes. Epistemic and aleatoric fields are optional and separate. The demo's raw
agent confidence and model epistemic number are declared **heuristics**. Conditional
return variance describes variation under the supplied model; it cannot identify
true environment aleatoric uncertainty or model epistemic error by itself.

Forecast/run/task/trajectory/version identities are checked against verified outcomes.
Information cutoff <= forecast timestamp < outcome timestamp. Duplicate forecasts
per method/task, duplicate labels, mixed scopes, mismatched versions and simulated
labels are rejected. Missing, censored and infrastructure outcomes stay unlabeled.
All benchmark verifiers run after execution; success is not inferred from tool status.

Calibration families 0–2 fit training; family 3 is validation, family 4 held-out test,
family 5 environment/tool distribution shift. No steps from the same scenario cross
splits. Calibrator artifacts contain training groups, provenance fingerprints, hash
and version; transform rejects overlap. This is offline held-out evaluation, not a
claim that a calibrator fitted later was deployed at the original forecast time.
Train-only Platt logistic fit and weighted PAVA isotonic interpolation are fixed
methods; neither is selected for release based on a favorable test score.

Brier, clipped binary log loss (epsilon=1e-12), fixed-bin ECE, equal-frequency ECE
(ties kept together), reliability bins, unpenalized slope/intercept, AUROC, stepwise
average precision and tie-preserving selective risk/coverage are reported. ECE is
bin-sensitive. Single-class AUROC/AP and unstable/separated slope fits are **null**.
Scenario-cluster percentile bootstrap conditions on the fitted calibrator; it does
not include calibrator refitting uncertainty. Task counts and independent group
counts are both visible. Calibration deterioration under shift remains visible.

## Planning and horizon protocols

Greedy uses highest sampled immediate reward; expected value uses cumulative reward;
mean–variance subtracts lambda times return variance; CVaR subtracts lambda times
upper-tail loss CVaR. Optional uncertainty-CVaR also subtracts the explicitly
uncalibrated uncertainty heuristic. Loss is negative cumulative reward. CVaR
integrates the worst (1-alpha) empirical mass, including a fractional boundary
sample; alpha=0 is mean loss. It can be negative for profitable outcomes.

All methods share candidate generation, conditional prediction streams and per-
decision budgets. Total work may differ after real states diverge; report those
differences. The one-factor screening grid covers K=2/4/8, M=8/16/32, H=1/3/5/10,
lambda=0/.1/.5/1 and alpha=.8/.9/.95, plus an underestimated-tail model. This is
not a full factorial study, a tuned production policy or evidence that planning
beats an authoritative rule policy. The v0.5 safe-rule control remains available.

Horizon configs cover 1/2/4/8/16/32. Three protocols remain separate:

* Teacher-forced **one-step** predictions consume actual prior state.
* Free-running open-loop predictions accumulate hypothetical state.
* Closed-loop observed execution evaluates aligned windows between real actions.

When replanning changes the action sequence, the original counterfactual sample
set is entirely excluded from labeling, rather than filtering favorable samples.
Absorbing terminal states permit horizon comparison after early completion/failure.
Success-by-horizon is distinct from eventual task success. State MAE/RMSE/CRPS apply
only to explicitly numeric health/progress; no text RMSE. Long-horizon metrics
include sample counts and bootstrap intervals. Closed-loop coverage may shrink at
large H; do not compare different coverage as if tasks were equivalent.

Replan trigger thresholds are explicit synthetic screening settings. False/missed
trigger diagnostics use a configured material numeric error, not verified causal
necessity of a replan. They are **not production-validated drift detectors**.
Failure categories are supporting hypotheses (including possible compounding error,
planner exploitation, distribution shift and excessive cost), with replay links;
one unexpected rare failure does not prove a model is miscalibrated.

## Existing replay and CI integration

```bash
agent-replay benchmark compare .replay/research/risk/expected_value .replay/research/risk/cvar
agent-replay probabilistic replay .replay/research/risk/cvar risk-scenario-0-seed-0 \
  --output .replay/research/recorded-replay.json
```

Recorded playback has zero model/tool executions. Root decisions and candidate
scores are visible in the existing replay view; full H×M futures are linked under
`research/<planning-id>.json`. Alternative outcomes are simulated-only.

An existing release policy may add:

```json
{
  "environment": "DEVELOPMENT",
  "min_tasks": 20,
  "critical_tags": [],
  "inconclusive_action": "allow",
  "probabilistic": {
    "baseline_run_id": "COPY_THE_EXPLICIT_BASELINE_RUN_UUID",
    "min_labeled_samples": 200,
    "min_groups": 20,
    "max_brier_regression": 0.02,
    "max_severe_failure_regression": 0.02,
    "max_success_rate_regression": 0.03
  }
}
```

```bash
agent-replay benchmark gate --baseline BASELINE_RUN --candidate CANDIDATE_RUN \
  --policy policy.json --output quality-gate.json
```

The opt-in extension verifies an explicit baseline/run version and reconstructs
metrics from saved verifier results and pre-outcome forecasts. Paired scenario-
cluster confidence intervals and Holm-corrected sign-randomization tests support
decisions. Missing data, inadequate independent coverage or uncertain threshold
crossing produces INCONCLUSIVE. Existing replay/critical-task checks still apply.
Existing release statistics now cluster repeated task trials instead of assuming
every seed is an independent task. Exit codes remain 0 allowed, 1 FAIL, 3 blocking
INCONCLUSIVE, 2 invalid configuration. Development policy above deliberately allows
inconclusive research; production retains the existing blocking default. Do not
enable a production probabilistic release gate from a small synthetic screen.

`.github/workflows/probabilistic.yml` uses only `contents: read`, normal PR events,
no secrets or privileged fork execution. It uploads reports, validates recorded
replay, checks an explicitly inconclusive comparison and a self-comparison positive
control. Numerically known FAIL cases are tested separately; the self-comparison
does not establish prediction quality.

## Resource and compatibility boundaries

All defaults are validated in ExperimentConfig/SamplingConfig. Per-decision call,
token reservation, time and sidecar limits compose with experiment-wide prediction,
elapsed-time and storage caps. Budget exhaustion interrupts the experiment and
leaves tasks censored, never silently successful. Synthetic tool charges are fixture
units; actual external provider charges/model tokens are zero. Linux peak RSS,
elapsed time, artifact bytes/task, tool calls and planning overhead are recorded.
These local timings are not SLAs; concurrent workloads affect them.

No SQL migration, trajectory v2 bump, new orchestration service or mandatory
dependency. New associated JSON schemas coexist with v0.5. New code uses existing
sanitized atomic storage. Large raw research data stays local/private; normal
server/tenant access boundaries are unchanged. CLI executes only bundled synthetic
dynamics; arbitrary SDK Python callbacks remain trusted code, not an OS sandbox.

Rollback: disable/remove the opt-in probabilistic gate and use v0.5. Retain immutable
research evidence for audit. Existing benchmark/replay/regression/rollout and SaaS
routes retain their API behavior. Optional live-provider, GPU and real-world task
quality remain unvalidated by these CPU experiments.
